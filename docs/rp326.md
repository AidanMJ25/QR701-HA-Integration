# Rongta RP326 Thermal Printer for Home Assistant

An independent `rp326` custom integration adapted from this repository's QR701
integration. Requires Home Assistant 2026.11 or newer and `serialx==1.15.1`.
The existing QR701 integration is unchanged. No physical RP326 testing has been
performed: native QR, styles, status bits and cutter behavior need validation on
your firmware before unattended use.

## Installation

Copy `custom_components/rp326` to `/config/custom_components/rp326`, restart Home
Assistant, then add **Rongta RP326 Thermal Printer** in Devices & services.
Use manual installation for this second integration; this repository's existing
HACS metadata targets QR701 and is not a separate RP326 distribution.

Select the ESPHome serial proxy (or a local RS-232 serial adapter), match the
printer's actual baud rate, and enable hardware status only with bidirectional
wiring and firmware supporting `DLE EOT 1..4`. Supported baud choices are 9600,
19200, 38400 and 115200 with 8-N-1. **9600 is a UI/example default, not a claim
about the printer's factory default.** Print its self-test page first.
Reconfigure from the integration menu to change settings. Setup does not print.

## ESP32 wiring

Use [the ESPHome example](../examples/esphome-rp326.yaml). The printer requires
its own specified 24 V supply. Never power it from the ESP32 or MAX3232.

| ESP32 / converter | Printer DB9 |
| --- | --- |
| GPIO17 → MAX3232 T1IN → T1OUT | Pin 3 RXD |
| GPIO16 ← MAX3232 R1OUT ← R1IN | Pin 2 TXD |
| Common signal ground | Pin 5 GND |

Power a 3.3 V compatible MAX3232 module at 3.3 V. The DB9 is **RS-232**, not TTL;
GPIOs must connect through the converter. `port_type: RS232` describes the port;
it does not perform electrical conversion. Pin numbers above refer to the
printer, not an assumed pinout on your converter board. Verify the board/cable
pinout. A standard PC DTE RS-232 adapter uses a straight-through cable; converter
boards vary. Printer pins 6/8 are busy/ready outputs, not extra data pins.

This implementation inherits the QR701's paced 32-byte writes and **does not
implement hardware or software flow control**. Do not assume pacing satisfies
RTS/CTS or XON/XOFF. Use this three-wire setup only if the printer can operate
without active handshaking; otherwise a flow-control-capable transport must be
implemented before relying on long jobs. UART logging and other printer drivers
must not share this UART. For TX-only use, omit `rx_pin` and disable status.

## Features

- Literal text and Markdown with wrapping at 48 Font A columns for the 80 mm
  configuration (576 dots); H1 wraps at 24 double-width columns. The optional
  58 mm/384-dot printer mode is not supported by this layout.
- Headings, inline bold/italic/underline, lists, quotes, links, rules and fenced
  code; styles depend on firmware. Strikethrough is represented by underline.
- Native QR codes: UTF-8 payload, size 1–16, correction L/M/Q/H.
- UPC_A, UPC_E, EAN13, EAN8, CODE39, ITF, CODABAR, CODE93 and CODE128 barcodes.
- Three restored editable drafts, QR size/correction controls, seven buttons,
  status sensor, and optional paper-out, cover-open and error sensors.
- Serialized print jobs/status polling, reconnect after failure, no automatic
  replay of partial receipts. `sending` means transmission, not completion.

Text uses ASCII with unsupported characters replaced by `?`. QR encodes UTF-8.
Long symbols may exceed the 576-dot print area; reduce size or payload length.
No raster/image fallback, cash-drawer action or additional barcode types are
implemented. Status polls every 30 seconds using four sequential real-time
queries. Disable status if firmware replies are unsupported. Unknown status
with status disabled does not prove that the printer is ready or powered.

## Actions

All actions require `device_id` in `data`, selecting a loaded RP326 device.

| Action | Fields and defaults |
| --- | --- |
| `rp326.print_text` | `text`, up to 32768 characters |
| `rp326.print_markdown` | `text`, up to 32768 characters |
| `rp326.print_qr` | `text` (1–7092 UTF-8 bytes), `size: 5`, `error_correction: M` |
| `rp326.print_barcode` | `text`, `format: CODE128`, `height: 80` (1–255), `width: 2` (2–6), `show_text: true` |
| `rp326.feed` | `lines: 3` (0–255) |
| `rp326.cut` | `lines: 3` (0–255), feeds then requests partial cut using `GS V 1` |
| `rp326.refresh_status` | No other fields |

Printing does not cut automatically. Use an explicit sequence to print and cut:

```yaml
sequence:
  - action: rp326.print_markdown
    data:
      device_id: YOUR_RP326_DEVICE_ID
      text: |-
        # Shopping list
        - Coffee
        - Milk
  - action: rp326.cut
    data:
      device_id: YOUR_RP326_DEVICE_ID
      lines: 3
```

Each print already feeds three trailing lines. The cut action adds its own feed;
adjust `lines` after checking the physical print-head-to-cutter distance. Actual
cut style varies with firmware; a full cut is not promised.

## Validation

The RP326 suites mirror the QR701 protocol, transport, and HA lifecycle tests and
add cutter coverage. CI runs both integrations. Local validation passed 31 protocol and in-memory transport tests across both
integrations, with only the serialx connection entry point stubbed because the
dependency could not be downloaded. Python compilation and JSON validation also
passed. Real serialx socket tests, Home Assistant lifecycle tests and Ruff could
not run locally: required packages were unavailable and PyPI DNS access failed.

```sh
python -m unittest discover -s tests -p 'test_standalone*.py' -v
python -m pytest tests/test_integration*.py -v
```
